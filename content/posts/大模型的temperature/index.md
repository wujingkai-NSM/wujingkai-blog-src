## 什么是 Temperature？

Temperature（温度）是大语言模型中的一个重要超参数，它控制着模型输出文本的**随机性**和**创造性**。

## Temperature 的作用

### 工作原理

在语言模型中，模型会为每个可能的输出 token 计算一个概率分布。概率分布是怎么从原始打分（logits）变来的？这一步由 Softmax 完成，详见 [Softmax是什么？大模型利用softmax做了什么]({{< ref "/posts/softmax" >}})。Temperature 通过以下方式影响这个分布：

```python
import numpy as np

def apply_temperature(logits, temperature):
    # 应用温度缩放
    scaled_logits = logits / temperature

    # 应用 softmax 得到概率分布
    probabilities = np.exp(scaled_logits) / np.sum(np.exp(scaled_logits))
    return probabilities
```

也就是说，Temperature 是作用在 logits 上的一个**缩放系数**：

- **T → 0**：logits 之间的差距被放大，概率分布变得"尖锐"，模型几乎总是选概率最高的 token（趋近贪心解码）
- **T = 1**：原始分布，不做任何改动
- **T > 1**：差距被压缩，分布变"平坦"，低概率的 token 也有机会被选中

它叫"温度"是借用了统计物理中玻尔兹曼分布的概念，和模型训练时的任何"热度"无关——它是**推理时**的参数，不改变模型权重。也就是说，Temperature 作用后的 logits 为 \(\frac{\text{logits}}{T}\)，再送入 softmax：

$$P(x_i) = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

### 一个直观的例子

输入"世界上最高的山是"，假设模型的 logits 如下，不同 Temperature 下的概率分布会变成：

| token | logit | T=0.5 | T=1 | T=2 |
|---|---|---|---|---|
| 珠穆朗玛峰 | 10 | ~99.9% | ~98% | ~70% |
| 乔戈里峰 | 6 | ~0.1% | ~1.8% | ~12% |
| 富士山 | 3 | ≈0 | ~0.2% | ~5% |
| 泰山 | 1 | ≈0 | ≈0 | ~3% |

Temperature 越低输出越确定、越可复现；越高则越发散、越多样，但也越容易胡说。

## 不同场景下的取值

### 低温度（0 ~ 0.3）：确定性优先

- **代码生成**：让模型写一个排序函数，T=0.2，希望每次输出规范的实现，而不是"创造性地"发明语法错误
- **数据抽取 / 格式化**：从合同里抽日期转 JSON，T=0，输出必须严格符合 schema
- **数学推理**：中间步骤一旦随机偏航，整条推理链就错了
- **事实问答**：T 高时模型可能把"珠穆朗玛峰"换成"乔戈里峰"甚至"富士山"（见上表）

### 中温度（0.5 ~ 0.9）：平衡

- **通用聊天助手**：既要准确，又不想每句话都像复读机
- **摘要、翻译**：需要在忠实原文和自然表达之间取平衡

### 高温度（1.0 ~ 2.0）：多样性优先

- **创意写作**：写诗、编故事、头脑风暴广告语，T=1.2 以上会让用词更出人意料
- **起名、文案变体**：需要同一 prompt 产出很多不同候选时，高 T + 多次采样
- **反面教材**：客服问答用 T=1.5，模型可能"创造性地"承诺不存在的退款政策

一个常见误解要澄清：**降低 Temperature 不等于提高正确率**。Temperature 只是重塑模型已有的分布，如果模型本身不知道答案，T=0 只会让它更自信地一本正经胡说。

## 为什么需要 Temperature

核心问题是：**为什么不让模型永远选概率最高的 token？**

1. **纯贪心会退化**。反复选最高概率 token 容易陷入循环重复（"很好很好很好很好…"），输出平淡、模板化。轻微的随机性反而让语言更自然。
2. **语言本身有合法的多样性**。"今天天气很好"和"今日天朗气清"在续写下都合理，这些候选都该有机会出现；Temperature 给了我们调节"该出现多少"的旋钮。
3. **不同任务对随机性的容忍度不同**。不存在单一最优值，所以必须把它暴露成可调参数，让调用方按场景在"可复现"和"创造性"之间做取舍。
4. **工程可控性**。T=0（或极低）+ 固定 seed 可以近似获得确定性输出，利于测试和缓存；创意任务则调高。一个参数覆盖了两种需求。

## 小结

- Temperature 是 softmax 前的 logits 缩放系数，控制采样分布的尖锐程度
- 它不改变模型本身，只改变"从分布里怎么选"
- 事实性、结构化任务用低温度；创意、多样化任务用高温度
- 它是随机性的旋钮，不是正确性的旋钮
